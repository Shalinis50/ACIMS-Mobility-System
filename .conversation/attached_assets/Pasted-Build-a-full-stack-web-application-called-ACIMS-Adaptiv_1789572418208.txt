Build a full-stack web application called:

ACIMS
Adaptive Campus Mobility Intelligence System

Tagline:
"Never miss your bus. Never wonder where it is."

IMPORTANT:
This is a college transportation management and student assistance system.
Build the application as a real, functional project with clean, editable source code.
Do NOT create a static mockup or a landing page.
All source code must remain accessible in the project.

TECH STACK:
- Frontend: React + Vite
- Styling: Tailwind CSS
- Backend: Node.js + Express
- Database: Use a simple local/data-layer abstraction initially so the app works without paid services.
- Maps: Use Leaflet + OpenStreetMap so there is no paid map API requirement.
- Make the architecture ready to replace the mock GPS data with real GPS later.
- Use JavaScript/TypeScript consistently throughout the project.

PHASE 1 PRIORITY:
Build these three core features first:

1. LIVE BUS TRACKING
2. SMART NOTIFICATIONS
3. QUEUE / OVERFLOW SEAT SYSTEM

Do NOT build unnecessary features before these three are working.

- Update its latitude/longitude periodically.
- Move between stops.
- Detect the next stop.
- Calculate approximate ETA.
- Update the UI automatically.

5. QUEUE / OVERFLOW SEAT SYSTEM
--------------------------------------------------

This is a major feature.

The student should NOT reserve a seat normally.

Instead:

If occupancy is below capacity:
Show:
"Seats available"

If occupancy reaches capacity:
Show:

BUS FULL
40/40 occupied

"Join the overflow queue for a seat."

Button:
JOIN QUEUE

When clicked:
Add the student to the queue.

Display:

QUEUE POSITION
#4

Estimated availability:
Based on current occupancy and expected passenger drop-offs.

Show:
"You are in the overflow queue."

Allow:
LEAVE QUEUE

The queue must persist during the session.

Create backend endpoints:

POST /api/queue/join
GET /api/queue/status
POST /api/queue/leave

Queue object should contain:
- studentId
- busId
- boardingStop
- queuePosition
- joinedAt
- status

Prevent duplicate queue entries.

--------------------------------------------------
12. IMPORTANT DEVELOPMENT RULES
--------------------------------------------------

Before finishing:

1. Make sure the application actually runs.
2. Make sure frontend and backend communicate correctly.
3. Make sure the Live Map works.
4. Make sure the simulated bus moves.
5. Make sure ETA changes.
6. Make sure notifications trigger based on bus state.
7. Make sure joining the queue works.
8. Make sure leaving the queue works.
9. Make sure queue position is calculated correctly.
10. Make sure the UI updates without requiring a manual page refresh.
11. Handle API errors gracefully.
12. Do not use paid APIs.
13. Do not add secret API keys.
14. Do not hardcode secrets.
15. Keep all code editable and visible in the Replit project.

After implementing, run the application and test the complete flow:

BUS 12 → moving → approaching Tambaram → notification → bus full → student joins queue → queue position displayed.

Only after the core flow works should you add visual polish.
